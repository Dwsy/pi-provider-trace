# Issue: 深度回合可观测性与 Turn 树 UI

## Goal

对齐 pi-langfuse 的 prompt → turn → generation/tool/message 层级，在 pi-provider-trace 中捕获用户消息、工具入参/出参、assistant 消息全文，并以 Turn 树为主导航重做 Web UI。

## 背景/问题

- 既有 UI 以 HTTP exchange 为中心；`pi_event` 几乎只有 summary，tool/message 无正文。
- pi-langfuse 已证明层级模型：`agent.prompt` → `agent.turn` → `llm-response` / `tool:*`。
- 用户要求「事无巨细」的会话回合可观测，并允许大改 Web UI。

## 验收标准 (Acceptance Criteria)

- [x] WHEN `/trace on` 捕获 tool_call/tool_result/message_end/input，系统 SHALL 在 JSONL `detail` 中写入有界全文（args/result/text）。
- [x] WHEN 打开 Web UI，系统 SHALL 默认以 Session → Prompt → Turn → Node 树呈现。
- [x] WHEN 选中 tool 节点，系统 SHALL 显示完整 arguments 与 result 文本。
- [x] WHEN 选中 generation 节点，系统 SHALL 保留既有 wire 证据页签（flow/payload/headers/…）。
- [x] WHERE 历史数据仅有 HTTP，系统 SHALL 可切换「请求」账本视图。
- [x] `npm test` 全绿（含 tree + capture）。

## 实施阶段

### Phase 1
- [x] 对照 pi-langfuse lifecycle 与 Pi extension event types
- [x] 定位 compactDetail 截断根因

### Phase 2
- [x] 重写 `pi-events.ts` 有界全文捕获 + turnIndex/exchangeId 关联
- [x] `model.js` buildSessionTree / selectTreeNode
- [x] Web UI 回合树 + 节点详情 + 列表模式切换

### Phase 3
- [x] tree.test.mjs / pi-events-capture.test.mjs / npm test

## 关键决策

| 决策 | 理由 |
|------|------|
| 不接生产 Langfuse | 沿用本地 JSONL + UI；层级语义对齐即可 |
| 捕获预算 24k–48k chars | full-debug 默认；避免无限 JSONL 膨胀 |
| 保留「请求」账本视图 | 兼容旧日志与 wire 排障 |
