# Issue: 开发者可观测性工作台重构

## Goal

将 Web UI 重构为面向 Pi 开发者排障的可观测性工作台，使用户能按 **Session → Request → Evidence** 快速定位 Pi 上下文、流式请求、工具调用、耗时、成本和原始证据；实时增量只保留内存，流结束只持久化一条最终结果。

## 背景/问题

当前页面混合 Apple 展示层、仿窗口装饰和八个同级 tab，弱化了诊断工作流。会话级数据与单次 HTTP 交换数据没有明确边界；移动端垂直堆叠三栏，主检查区不足。用户确认目标受众是需要审计 Pi 会话事件和 LLM 请求流的服务开发者。

## 验收标准 (Acceptance Criteria)

- [x] WHEN 开发者查看历史或实时 Pi 会话，系统 SHALL 以 Session → Request → Evidence 的层级呈现数据。
- [x] WHEN 选择某次 Request，系统 SHALL 优先显示 endpoint、provider、HTTP 状态、TTFT、总耗时、成本及流式完成状态。
- [x] WHERE Inspector 中，系统 SHALL 以联动视图串起 Pi Context → HTTP → Model Stream → Tool Calls，并提供 Input / Output / Timeline / Raw 证据页签。
- [x] IF 视口宽度小于 800px，THEN 系统 SHALL 以单面板路径浏览会话、请求和证据，不垂直挤压三个区域。
- [x] 系统 SHALL 通过增量 patch 只在内存维护当前实时快照，并只持久化一条 `stream_result`；跨 Request 工具结果关联仍可用。
- [x] 系统 SHALL 通过完整测试、静态 UI 校验、diff 检查和桌面/移动端浏览器验收。

## 关键决策

| 决策 | 理由 |
|------|------|
| 维持桌面三栏，但彻底重写语义与视觉 | 调试时需同时保留会话上下文、请求列表与原始证据；三栏不是旧 DOM/样式的延续。 |
| 移动端单面板路径 | 小屏不能同时容纳三栏；使用显式返回路径避免 60dvh 导航挤压证据。 |
| 代码与协议数据保留等宽字体 | URL、JSON、SSE、工具参数及 HTTP 方法需要字符对齐；普通导航与状态不需要。 |
| 不再把仿窗口作为语义容器 | 装饰不能与操作层级竞争，Inspector 直接表达诊断范围。 |
| 实时快照与持久事实分离 | `stream_update` 是当前查看状态；`stream_result` 才是历史事实，避免 JSONL 写放大。 |
| 使用原生 ES Modules | 本地扩展需要零构建、离线和低启动成本；不 vendoring Alpine/Prism。 |
