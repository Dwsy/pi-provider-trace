# Issue: Apple 原生视觉重构

## Goal

将 pi-provider-trace Web UI 从 Factory/工业风改为克制的 Apple 原生界面：系统色、半透明材质、清晰层级、舒适的列表密度与无障碍动效，同时不改变任何追踪或调试行为。

## 验收标准

- [x] 浅色与暗色主题使用 Apple 风格的系统背景、文字、蓝/绿/橙/红语义色和材质层级。
- [x] Header、侧栏 List、Tab 切换、表单控件、详情卡片和工具调用卡保持一致的原生圆角、边界、焦点与按压反馈。
- [x] 页面支持 `prefers-reduced-motion` 与 `prefers-reduced-transparency`，移动端三栏布局不重叠。
- [x] UI 重构未改动 HTTP/SSE 捕获、数据模型或既有工具调用可视化逻辑。

## 实施阶段

### Phase 1: 规划和准备
- [x] 审计 Factory 样式、CSS 装载顺序与现有未提交改动。
- [x] 定义系统色、字体、材质、圆角和动效 token。

### Phase 2: 执行
- [x] 重写全局 tokens，移除远程字体和 Factory 色板。
- [x] 重构最终加载的 chrome 层，统一 header、列表、tabs、详情卡片、控件与代码块。
- [x] 增加动效/透明度降级和移动端 2×4 Tab 布局规则。

### Phase 3: 验证
- [x] 运行完整测试和静态 UI 校验。
- [x] 浏览器验证浅色、暗色和 iPhone 14 布局，无控制台错误。
- [x] 审查 diff，确认没有覆写既有功能改动。

## 关键决策

| 决策 | 理由 |
|------|------|
| 仅重构 CSS token 与最终 chrome 覆盖层 | 保持现有多文件原生 JS 架构和所有调试行为稳定。 |
| 使用平台系统字体而非远程字体 | 延续 macOS/iOS 的字形、可访问性和加载性能。 |
| 信息密度保持开发工具级别 | Apple 的“简洁”不是隐藏诊断数据，而是用层级和间距降低认知负担。 |
| 移动端 Tab 改为 2×4 网格 | 所有调试视图无需横向滚动即可触达。 |
