# Issue: 跨会话总览与工作台交互打磨

## Goal

在既有「Session → Turn → Node」工作台之上补一层跨会话视图，用同一批 JSONL 事实回答「哪个模型在烧钱」「这周延迟是否退化」「哪些会话在报错」；同时修掉工作台里实际会硌手的交互问题。

## 背景/问题

工作台回答「这次会话发生了什么」很好，但要回答任何跨会话的问题，只能一个个点开会话人工比对。成本、TTFT、错误率这些本来已经在 `llm_usage` 里逐条记着，却没有任何聚合出口。

另外三栏列表一次性渲染全部行，会话/请求多时明显卡顿；键盘只有 `/` 聚焦搜索，列表要靠鼠标；部分面板空态是一片空白。

## 验收标准 (Acceptance Criteria)

- [x] WHEN 请求 `/api/overview`，系统 SHALL 按冻结契约返回 totals / sessions / models / providers / timeline。
- [x] WHEN 某项测量无样本，系统 SHALL 返回 `null` 且前端 SHALL 渲染 em dash，SHALL NOT 返回或渲染 `0`。
- [x] WHEN 窗口为 `24h`，系统 SHALL 按小时分桶，其余按天分桶，且 SHALL 零值补齐。
- [x] WHEN 点击总览中的会话行，系统 SHALL 跳回工作台并选中该会话。
- [x] WHERE 历史日志仅有 `sse_line`，系统 SHALL 仍能聚合。
- [x] WHEN 列表行数很多，系统 SHALL 增量渲染而非一次性铺开。
- [x] 系统 SHALL 通过 `npm test`（含新增 `overview.test.mjs`）与静态 UI 闸门。

## 关键决策

| 决策 | 理由 |
|------|------|
| 总览是平级独立界面，不是第四栏 | 三栏已经承载「单会话下钻」，再塞一栏会同时挤压两种任务；跨会话是另一种意图。 |
| 空样本返回 `null` 而非 `0` | `0 ms` 表示测到了零，`null` 表示没测到。后端混淆二者，前端就无法诚实呈现。 |
| 抽出 `read-session-log.ts` 而非在 overview 里复制读取逻辑 | 复制会让 8 MiB 尾读上限与 legacy 折叠在两处漂移；抽出后 `legacy-sse-compaction.test.mjs` 无需改动仍通过。 |
| 复用既有 fold/derive，不新增采集 | 这是一个纯读侧聚合，改采集路径的风险与收益不成比例。 |
| 无法解析模型的 exchange 归入 `unknown` 而非丢弃 | 丢弃会让总量对不上，读者无从察觉。 |
