# Issue: 工具调用可视化与流式增量

## Goal

在 HTTP exchange 的 Streaming 面板中，将已捕获的原始 SSE 重放为结构化工具调用卡片：工具名、实时 arguments、完成状态与后续请求中关联的 tool result。

## 背景/问题

当前 UI 仅从 SSE 提取文本 delta。OpenAI 与 Anthropic 的工具调用使用不同 SSE 事件和参数分片格式，因此 tool_use、arguments 和 tool result 无法被识别或实时呈现；原始 wire events 虽可查看，但不适合高频 Coding Agent 调试。

## 验收标准 (Acceptance Criteria)

- [x] WHEN Anthropic `content_block_start` / `input_json_delta` / `content_block_stop` 到达，系统 SHALL 以稳定 call id 累积并实时展示工具名和 arguments。
- [x] WHEN OpenAI Chat Completions 或 Responses API 的工具调用 delta 到达，系统 SHALL 按 index、call id 或 item id 累积独立调用，且多调用交错时不串内容。
- [x] WHERE 后续请求包含 Anthropic `tool_result`、OpenAI `role=tool` 或 Responses `function_call_output`，系统 SHALL 将结果关联回原调用卡片。
- [x] IF arguments 仍是不完整或非法 JSON，THEN 系统 SHALL 原样显示，不抛出异常或阻断文本流。
- [x] 原始 SSE 详情 SHALL 保持可用；非工具文本流展示不得回归。

## 关键决策

| 决策 | 理由 |
|------|------|
| 在浏览器端从原始 SSE 重放 | 不改变已稳定的 wire capture 格式，也能让历史和实时数据使用同一算法。 |
| 用 call id 优先、provider index/item id 兜底 | OpenAI/Anthropic 标识符的出现时机和字段不同，且早期 delta 未必带 call id。 |
| tool result 从后续请求体跨 exchange 查找 | 工具执行结果不在上一个模型响应的 SSE 中，必须关联下一个请求。 |
| 不静默解析/截断 parameters | 调试视图应保留不完整 delta 的可观测性。 |
